# Ручная проверка

Подробный чек-лист для проверяющего. Каждый шаг устроен одинаково: что сделать, что должно появиться в AdRobot, что должно оказаться в админке Keitaro. Короткая версия на десять минут есть в [README](../README.md#проверка-своими-руками-за-10-минут).

Обозначения. Офферы названы буквами: А, Б, В, Г, Д. Подставьте любые свои активные офферы. «Keitaro не меняется» значит: обновите страницу кампании в админке и убедитесь, что там всё по-прежнему.

## 0. Подготовка

1. Запустите приложение по [README](../README.md#быстрый-старт) и откройте http://127.0.0.1:8000. Лампа в шапке должна показать «Keitaro: на связи».
2. Откройте в соседнем окне админку Keitaro, раздел «Кампании». После каждого Push обновляйте там страницу кампании, как это делает автор видео.
3. Зайдите в «Настройки» и впишите своё имя в поле «Ваше имя для журнала операций». Оно понадобится в разделе 11.
4. Проверьте, сколько активных офферов видит ключ: на экране «Новая кампания» щёлкните в поле Offer, откроется список. Для полного сценария видео нужно пять офферов. Если их меньше, в разделе 2 есть вариант на три оффера.
5. Все проверочные кампании называйте с общим началом, например `adrobot-check`. Так их проще найти и убрать в разделе 17.

Трекера под рукой нет? Запустите `python scripts/demo_server.py` и откройте http://127.0.0.1:8001. Колонка «В админке Keitaro» в этом режиме не проверяется, всё остальное работает так же. В демо уже есть статистика, поэтому раздел 10 про советника удобнее проходить именно там.

### 1.4. Ошибки ввода

| № | Сделайте | В AdRobot | В админке Keitaro |
|---|---|---|---|
| 1 | Geo: `ZZ`, остальное заполнено, Create | Красный значок `ZZ ?`. Под формой: «Не распознано: ZZ.» Запрос не отправлен | Ничего |
| 2 | Geo: `UK` | Значок `GB · Великобритания`. После Create кампания создаётся | В фильтре Flow 1 стоит Великобритания. Сам Keitaro сохранил бы `UK` без ошибки, и фильтр никогда бы не сработал |
| 3 | Оставьте пустым Name, затем не выбирайте оффер | «Введите название кампании.», «Выберите хотя бы один оффер из списка.» | Ничего |
| 4 | В поле «Куда редиректить страну из Flow 1» впишите `google.com`, Create | «Адрес редиректа должен быть полным URL вида https://google.com.» | Ничего |
| 5 | Создайте кампанию с названием, которое уже есть в трекере | Сообщение: кампания с таким названием уже есть, указан её номер. Второй клик по Create создаёт дубль осознанно | После первого клика ничего. После второго появляется вторая кампания с тем же названием |
| 6 | В поле Alias впишите alias уже существующей кампании | Карточка «Не создана»: alias уже занят. Подмены на случайный alias нет | Ничего |
| 7 | Быстро щёлкните Create дважды | Кнопка блокируется на время запроса. Кампания одна | Одна кампания |

Несуществующий оффер в форме выбрать нельзя: поле принимает только варианты из списка. Проверьте отказ через API, в Swagger (`/docs`) или командой:

```bash
curl -s -X POST http://127.0.0.1:8000/api/campaigns \
  -H "Content-Type: application/json" \
  -d '{"name": "adrobot-check-bad", "geo": "AU", "offer_id": 999999999}'
```

Ожидается ответ 422 с кодом `validation`. В тексте сказано: «Оффер #999999999 не найден в Keitaro (или недоступен ключу API).» Кампания в трекере не появляется. Число длиннее десяти цифр тоже получает 422, а не ошибку сервера.

Идемпотентность удобно увидеть так же. Подставьте вместо `101` номер своего оффера и выполните команду дважды:

```bash
curl -s -X POST http://127.0.0.1:8000/api/campaigns \
  -H "Content-Type: application/json" -H "Idempotency-Key: adrobot-check-idem-1" \
  -d '{"name": "adrobot-check-idem", "geo": "AU", "offer_id": 101}'
```

Второй ответ повторяет первый и содержит `"replayed": true`. В Keitaro кампания одна. Тот же ключ с другим телом даёт 409 `idempotency_mismatch`.

## 3. Pin, ручная доля, «Пересчитать», «Выровнять поровну»

| 8 | «Выровнять поровну» | А 50, Б 50, закрепления сняты. Push доступен |

## 4. Конфликт с правкой в Keitaro

| № | Сделайте | В AdRobot | В админке Keitaro |
|---|---|---|---|
| 1 | В AdRobot сделайте черновик: добавьте оффер или задайте долю вручную | Поток жёлтый | Keitaro не меняется |
| 2 | В Keitaro откройте поток, на вкладке «Схема» измените долю или удалите оффер. «Применить», «Сохранить» | | Поток изменён |
| 3 | В AdRobot нажмите Push to KT | Диалог «Поток изменили прямо в Keitaro». В нём два списка: «Сейчас в Keitaro» и «AdRobot ожидал увидеть». Кнопки: «Отмена», «Fetch: подтянуть из Keitaro», «Опубликовать поверх» | Правка из шага 2 цела |

## 8. Оффер, недоступный ключу

Проверка возможна, если в трекере есть кампания, в потоке которой стоит оффер, не видимый вашему ключу. Например, его завёл другой пользователь.

| № | Сделайте | В AdRobot |
|---|---|---|
| 1 | На экране «Кампании» впишите номер такой кампании в поле KT ID и нажмите «Открыть по ID» | Вместо названия стоит «Оффер #N» с красной меткой «нет в справочнике». Доля взята из Keitaro |
| 2 | Сделайте любую правку с другими офферами и нажмите Push to KT | Публикация проходит. Незнакомый оффер остаётся в потоке со своей долей |
| 3 | Уберите такой оффер через Remove и опубликуйте. Затем нажмите у него Bring back и снова Push to KT | Оба действия проходят. Привязка уже бывала в трекере, значит, оффер существует. В Keitaro он вернулся в поток |
| 4 | Попробуйте добавить невидимый оффер в другой поток | В поиске его нет. Через API приходит отказ `offer_not_usable`: проверить существование нового невидимого оффера нечем |

Оффер, который справочник знает как удалённый или выключенный, блокируется всегда: ни Add, ни Bring back, ни Push с ним не пройдут.

## 9. Экран «Офферы»

Нужны две кампании с потоками офферов. Подойдут `adrobot-check-video` и `adrobot-check-mini` из раздела 2. Возьмите оффер, которого нет хотя бы в одной из них. Дальше он назван Е.

| № | Сделайте | В AdRobot | В админке Keitaro |

| 1 | «Офферы». В поиске найдите Е и выберите | Блок «Где используется»: потоки, где Е стоит, с долей и состоянием «в Keitaro». Блок «Куда можно добавить»: потоки с офферами, где его нет, с гео и числом офферов | Ничего |

| 4 | В Keitaro поменяйте что-нибудь в потоке второй кампании и сохраните | | Поток второй кампании изменён |

Публикация пачкой отправляет весь черновик каждого потока, а не только выбранный оффер. Перед ней стоит заглянуть в потоки с меткой «черновик».

## 10. Советник долей

Свежая кампания на настоящем трекере не имеет трафика, поэтому содержательный совет проще увидеть в демо-режиме. Отказы можно проверить где угодно.

| 2 | В демо-режиме откройте `campaign 2` и нажмите «Советник» у Flow 2 | Таблица: оффер, «Сейчас», «Предлагается», «Почему». В колонке «Почему» стоит сглаженный CR, число кликов и сдвиг в пунктах. Над таблицей сказано, что шаг ограничен 15 пунктами и каждому офферу оставлено не меньше 5 % |
| 3 | Сложите колонку «Предлагается» | Ровно 100 |
| 4 | Переключите «Сравнивать офферы» на EPC | Таблица пересчитана по доходу с клика |

| 11 | Оставьте в потоке два оффера, один из которых новый, и откройте советника | Отказ: данных хватает меньше чем по двум офферам, сравнивать пока нечего |
| 12 | Смените период статистики в шапке редактора и откройте советника снова | Совет считается по выбранному периоду |

## 11. Журнал

1. Откройте «Журнал». Каждый шаг из разделов выше записан отдельной строкой: «Создание кампании», «Проверка без создания», «Fetch streams», «Add», «Remove», «Bring back», «Pin», «Unpin», «Доля вручную», «Пересчёт долей», «Выравнивание долей», «Push to KT», «Cancel», «Откат к снимку», «Массовое добавление», «Публикация пачкой», «Синхронизация всех», «Доли от советника».
2. У неудачных операций красная метка «ошибка», в колонке «Что произошло» стоит текст ошибки. Примеры: отказ на долю 99 из раздела 3 и несозданная кампания с занятым alias из раздела 1.4. Создание, в котором не появилось ни одной кампании, считается ошибкой, хотя сам запрос отвечает кодом 200.
3. В колонке «Кто» стоит имя, заданное в подготовке. Журнал самого Keitaro видит только API-ключ.
4. В колонке «мс» стоит длительность операции вместе с запросами к трекеру.
5. Фильтр «Только ошибки» оставляет только красные строки. Кнопки внизу листают журнал по 50 записей.

## 13. Тёмная тема, мобильная ширина, клавиатура

1. «Настройки», поле «Тема»: выберите «Тёмная». Интерфейс перекрасился. Выбор сохраняется после перезагрузки. Вариант «Как в системе» следует за настройкой ОС.
2. Пройдите по экранам в тёмной теме: жёлтый поток, серые строки архива, шкала долей и диалоги читаются.
3. Сузьте окно до ширины телефона, меньше 720 px. Меню ушло на вторую строку. В таблице офферов скрылись колонки Stats и Trends. Таблицы прокручиваются по горизонтали. Форма создания стала одной колонкой.
4. Клавиатура. Первое нажатие Tab показывает ссылку «К содержимому». В поиске офферов работают стрелки, Enter и Esc. Диалог закрывается по Esc, фокус не уходит за его пределы и возвращается на кнопку, которая его открыла.
5. Откройте `/docs` при выключенном интернете. Swagger UI загрузился: его файлы лежат в репозитории.

ADROBOT_AUTH_TOKENS=anna:длинный-токен-анны,viewer:длинный-токен-гостя:ro

| № | Сделайте | Ожидается |
|---|---|---|
| 1 | Запустите приложение и обновите страницу | Диалог «Нужен токен доступа». В тексте названы оба вида токенов: общий и именной |

| 3 | Введите токен `anna` | Интерфейс работает. Токен хранится до закрытия вкладки, новая вкладка спросит его заново |

## 16. Несколько воркеров, замок и подкаталог

Этот раздел необязателен: он проверяет то, что в обычной работе не видно.

**Замок кампании.** Узнайте ID кампании в AdRobot: это число в адресе редактора, `#/campaigns/<ID>`. Повесьте замок вручную на 40 секунд, подставив свой ID вместо `1`:

```bash
python -c "import sqlite3; c = sqlite3.connect('data/adrobot.sqlite3'); c.execute(\"INSERT INTO campaign_locks VALUES (1, 'manual', datetime('now', '+40 seconds'))\"); c.commit()"
```

| № | Сделайте | Ожидается |
|---|---|---|
| 1 | Сразу нажмите в этой кампании Remove или pin | Кнопка ждёт около 20 секунд, затем приходит отказ: кампанию сейчас изменяет другой пользователь или процесс. Код `campaign_busy`, статус 409 |
| 2 | В другой кампании нажмите любую кнопку | Работает сразу: замок у каждой кампании свой |
| 3 | Подождите, пока пройдут 40 секунд, и повторите шаг 1 | Операция проходит. Просроченный замок убран |

**Несколько воркеров.** Запустите `uvicorn app.main:app --workers 2` и пройдите раздел 2. Поведение то же: замок лежит в базе и общий для всех процессов.

**Подкаталог за обратным прокси.** Если под рукой есть nginx, проверьте работу из подкаталога:

```nginx
location /adrobot/ {
    proxy_pass http://127.0.0.1:8000/;
}
```

Откройте `http://localhost/adrobot/`, обязательно со слэшем на конце. Интерфейс работает без настроек. Для кнопки Try it out на странице `/adrobot/docs` задайте в `.env` строку `ROOT_PATH=/adrobot`.

## 17. Как убрать за собой

1. Откройте проверочную кампанию в редакторе. Внизу страницы нажмите «Кампанию в архив» и подтвердите.
2. В AdRobot кампания пропадает из списка. В Keitaro она переносится в архив. Оттуда её можно восстановить, по документации архив хранится ограниченное время.
3. Повторите для каждой кампании с началом `adrobot-check`. Не забудьте пары из раздела 1.3 и дубль из раздела 1.4.
4. Кампании, созданные командами `curl`, тоже есть в списке AdRobot: они прошли через тот же API. Уберите их так же.
5. Скрипт `scripts/live_e2e.py` убирает свою кампанию сам, если не указан флаг `--keep`.

База AdRobot после проверок хранит журнал и скрытые кампании. Чтобы начать с чистого листа, остановите приложение, удалите файлы `data/adrobot.sqlite3*` и выполните `alembic upgrade head`.
